# ซิงค์ข้อมูลการบริบาลเภสัชกรรมไป Google Sheets

ฟีเจอร์นี้ส่งข้อมูลการบริบาลเภสัชกรรมแทบทุกหมวดที่บันทึกในแอพ RxClinic ไปเก็บไว้ใน Google Sheet
แบบทางเดียว (one-way export) เพื่อใช้ทำรายงาน/วิเคราะห์/แดชบอร์ดแยกต่างหาก — **Firestore ในแอพ
ยังเป็นฐานข้อมูลหลักเสมอ** สเปรดชีตนี้เป็นแค่สำเนาสำหรับดู/วิเคราะห์ ถ้าซิงค์ล้มเหลวหรือยังไม่ได้
ตั้งค่า แอพก็ยังใช้งานได้ปกติทุกประการ

ข้อมูลแยกเป็นชีตตามหมวดหมู่ อ่านง่าย ค้นหาง่าย มีสีประจำหมวดแยกแยะชัดเจน:

| ชีต | ข้อมูล |
|---|---|
| **Dashboard** | ภาพรวมทั้งหมด — การ์ดสรุป + ตัวชี้วัดคุณภาพ KPI1-7 + กราฟ |
| **Patients** | ทะเบียนผู้ป่วยทั้งหมด |
| **Visits** | บันทึกการบริบาลเภสัชกรรมทุกครั้ง (SOAP, ยา, adherence, เทคนิคพ่นยา, CAT/mMRC/ACT ฯลฯ) |
| **Telepharmacy** | การโทรติดตามผู้ป่วย |
| **DRP_Tracker** | ปัญหาจากการใช้ยา (Drug-Related Problems) ที่ตรวจพบ/ติดตาม |
| **Referrals** | การส่งต่อแพทย์เฉพาะทาง |
| **ADR_Reports** | รายงานอาการไม่พึงประสงค์จากยา |
| **MedReconciliation** | การทบทวนรายการยา (Admission/Discharge) |
| **Discharge_Counseling** | การให้คำปรึกษาก่อนกลับบ้าน |
| **RCA** | การวิเคราะห์สาเหตุที่แท้จริง (Root Cause Analysis) |
| **KPI_Snapshots** | ประวัติค่าตัวชี้วัดคุณภาพ KPI1-7 ทุกครั้งที่กดซิงค์ (ใช้ดูแนวโน้มย้อนหลัง) |

## ขั้นตอนตั้งค่า (ทำครั้งเดียว)

1. สร้าง Google Sheet ใหม่ (หรือใช้ชีตที่มีอยู่แล้ว) — ตั้งชื่อตามต้องการ เช่น "RxClinic — บริบาลเภสัชกรรม"
2. ในชีตนั้น ไปที่เมนู **ส่วนขยาย (Extensions) → Apps Script**
3. ลบโค้ดเริ่มต้นออก แล้ว **คัดลอกเนื้อหาทั้งหมดจากไฟล์ `Code.gs` ในโฟลเดอร์นี้** ไปวางแทน
4. ตั้งรหัสลับสำหรับยืนยันตัวตน (กันคนอื่นยิงข้อมูลปลอมเข้ามา):
   - ไปที่ไอคอนฟันเฟือง **Project Settings** (ด้านซ้าย) → เลื่อนลงไปที่ **Script Properties**
   - กด **Add script property** → Property: `SHARED_SECRET` → Value: ตั้งรหัสลับเอง (ยาวๆ สุ่มๆ เช่น
     `rxclinic-sync-2026-xxxxxxxx`) → Save
   - **จดรหัสนี้ไว้** จะต้องเอาไปกรอกในแอพด้วย
5. กลับไปที่แท็บ **Editor** เลือกฟังก์ชัน `setupDashboard` จาก dropdown ด้านบน (ข้าง ▶ Run) แล้วกด
   **Run** — ครั้งแรกจะมีหน้าต่างขอ authorize สิทธิ์ (กด Review permissions → เลือกบัญชี Google →
   Advanced → Go to (ชื่อโปรเจกต์) unsafe → Allow) หลังรันเสร็จจะเห็นชีตข้อมูลทุกหมวด (ดูตารางด้านบน)
   ถูกสร้างขึ้นพร้อมชีต "Dashboard" ที่มีกราฟ/การ์ดสรุป — ตัวชี้วัด KPI1-7 บน Dashboard จะขึ้น "—" จนกว่า
   จะกดปุ่ม "ซิงค์ตัวชี้วัด KPI" จากในแอพอย่างน้อย 1 ครั้ง (ดูขั้นตอนที่ 7)
6. Deploy เป็น Web App:
   - กดปุ่ม **Deploy** (มุมขวาบน) → **New deployment**
   - กดไอคอนฟันเฟืองข้าง "Select type" → เลือก **Web app**
   - Execute as: **Me (อีเมลของคุณ)**
   - Who has access: **Anyone** (จำเป็น — ไม่งั้นแอพยิง request เข้ามาไม่ได้ ความปลอดภัยใช้
     `SHARED_SECRET` แทนการจำกัดสิทธิ์ที่ระดับนี้)
   - กด **Deploy** → คัดลอก **Web app URL** ที่ได้ (ขึ้นต้นด้วย `https://script.google.com/macros/s/.../exec`)
7. เปิดแอพ RxClinic → **ตั้งค่า (Settings)** → แท็บ **📊 Google Sheet Sync** → วาง Web App URL +
   SHARED_SECRET ที่ตั้งไว้ในข้อ 4 → กด **ทดสอบการเชื่อมต่อ** ให้ขึ้น "เชื่อมต่อสำเร็จ" → เปิดสวิตช์
   "เปิดใช้งานซิงค์อัตโนมัติ" → กด **ซิงค์ย้อนหลังทั้งหมด** เพื่อนำข้อมูลเก่าทุกหมวดเข้า Sheet ครั้งแรก
   → กด **ซิงค์ตัวชี้วัด KPI ตอนนี้** เพื่อให้การ์ด KPI1-7 บน Dashboard มีค่าแสดงผล

หลังจากนี้ ทุกครั้งที่บันทึก/แก้ไขข้อมูลในแอพ (ผู้ป่วย, visit, telepharmacy, DRP, ส่งต่อแพทย์, ADR,
Med Reconciliation, Discharge Counseling, RCA) ข้อมูลหมวดนั้นจะถูกส่งไปอัปเดตใน Google Sheet
โดยอัตโนมัติ (แบบเบื้องหลัง ไม่ต้องรอ ไม่กระทบการบันทึกหลักในแอพแม้ซิงค์จะล้มเหลว) — ส่วนตัวชี้วัด
KPI1-7 ไม่ได้อัปเดตอัตโนมัติแบบ real-time (คำนวณจากข้อมูลทั้งคลินิกย้อนหลัง 12 เดือน ไม่เหมาะจะรันทุก
ครั้งที่บันทึก visit) ต้องกดปุ่ม "ซิงค์ตัวชี้วัด KPI ตอนนี้" เองเป็นระยะ (เช่นทุกสัปดาห์/เดือน)

## ถ้าต้องการอัปเดตโค้ด Apps Script ภายหลัง

แก้ไขโค้ดในแท็บ Editor ของ Apps Script โดยตรง (คัดลอกจาก `Code.gs` เวอร์ชันใหม่มาทับ) แล้วไปที่
**Deploy → Manage deployments → ไอคอนดินสอ (แก้ไข) → Version: New version → Deploy** — การ
แก้โค้ดเฉยๆ โดยไม่กด deploy เวอร์ชันใหม่จะไม่มีผลกับ Web App URL เดิมที่ใช้งานอยู่

ถ้าอัปเดตโค้ดจากเวอร์ชันเก่าที่มีแค่ชีต "Visits"/"Dashboard" มาเป็นเวอร์ชันนี้ (มีชีตหมวดอื่นเพิ่ม) —
รัน `setupDashboard` ซ้ำอีกครั้งเพื่อสร้างชีตใหม่ที่ยังขาดอยู่ (ไม่กระทบข้อมูลเดิมในชีต Visits ที่มีอยู่)

## โครงสร้างข้อมูลที่ส่งไป

ดูรายละเอียดคอลัมน์ทั้งหมดของแต่ละชีตได้จาก `HEADERS` ในไฟล์ `Code.gs` — ทุกหมวด (ยกเว้น
KPI_Snapshots) ใช้ ID คอลัมน์แรกเป็นตัวระบุ upsert (แก้ไขข้อมูลเดิมในแอพ = อัปเดตแถวเดิมในชีต ไม่สร้าง
แถวซ้ำ) ส่วน KPI_Snapshots เพิ่มแถวใหม่ทุกครั้งที่กดซิงค์ (เก็บเป็นประวัติ time-series สำหรับดูแนวโน้ม)

## ความเป็นส่วนตัวของข้อมูล

ข้อมูลที่ส่งไปมีชื่อ-HN-ประวัติทางคลินิกของผู้ป่วยจริง — ต้องเก็บ Google Sheet นี้ให้ปลอดภัย
(ไม่แชร์แบบเปิดสาธารณะ "Anyone with the link can view" ควรจำกัดเฉพาะบัญชีที่เกี่ยวข้องในคลินิก
เท่านั้น) และเก็บ `SHARED_SECRET` เป็นความลับเหมือนรหัสผ่าน
